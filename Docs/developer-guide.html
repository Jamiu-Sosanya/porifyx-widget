2 Application Architecture

The application follows a standard Laravel MVC architecture with some additional patterns layered on top for scalability and maintainability.

Request Flow — Web Widget Chat

  1. 1
    Visitor sends a message via the embedded JavaScript widget on a client's website. The JS widget posts to POST /api/chat/{widgetId}/message.
  2. 2
    API Controller validates the request, resolves the widget and its settings, and dispatches a ProcessChatMessage job to the queue.
  3. 3
    Queue Worker picks up the job. The RAGService embeds the question and queries the knowledge base for the top-K most relevant document chunks.
  4. 4
    AI Provider (OpenAI/Claude/Gemini/Groq) receives the system prompt, conversation history, and retrieved knowledge chunks. It generates a response.
  5. 5
    Response is saved to the messages table. Sentiment analysis runs asynchronously. Lead extraction checks the message for contact information.
  6. 6
    Real-time push via Laravel Reverb broadcasts the response back to the widget via a private Echo channel. The visitor sees the reply instantly.

Request Flow — External Channel (e.g. Telegram)

  1. 1
    Telegram Bot API sends a webhook POST to /webhook/telegram/{channelConfigId} when a user messages the bot.
  2. 2
    Channel Controller verifies the webhook signature, resolves the ChannelConfiguration record, and normalises the payload into a standard internal message format.
  3. 3
    The same ProcessChatMessage job is dispatched — the AI pipeline is identical regardless of which channel the message arrived from.
  4. 4
    Channel Driver (e.g. TelegramDriver) sends the AI response back to the user via the channel's outbound API.

Service Layer

Heavy business logic lives in service classes under app/Services/, not in controllers. Key services:

5 Channels Architecture NEW

The omnichannel system is built around a driver pattern. Every channel implements the same interface, so adding a new channel requires only writing a driver class — no changes to the core AI pipeline.

ChannelDriverInterface

// app/Channels/Contracts/ChannelDriverInterface.php interface ChannelDriverInterface { // Verify the webhook payload signature from the provider public function verifyWebhook(Request $request, ChannelConfiguration $config): bool; // Normalise the inbound payload into a standard InboundMessage DTO public function parseInbound(Request $request, ChannelConfiguration $config): InboundMessage; // Send the AI response back to the user via the channel's API public function sendOutbound(OutboundMessage $message, ChannelConfiguration $config): void; // Register the webhook URL with the channel provider (called on channel save) public function registerWebhook(ChannelConfiguration $config): bool; // Return the credentials schema (field names and validation rules) public function credentialsSchema(): array; }

Driver Registration

Drivers are registered in config/channels.php. The ChannelDispatchService reads this map to resolve the correct driver at runtime.

// config/channels.php return [ 'drivers' => [ 'web' => \App\Channels\Drivers\WebDriver::class, 'whatsapp' => \App\Channels\Drivers\WhatsAppDriver::class, 'telegram' => \App\Channels\Drivers\TelegramDriver::class, 'facebook' => \App\Channels\Drivers\FacebookDriver::class, 'instagram' => \App\Channels\Drivers\InstagramDriver::class, 'slack' => \App\Channels\Drivers\SlackDriver::class, 'discord' => \App\Channels\Drivers\DiscordDriver::class, 'sms' => \App\Channels\Drivers\SMSDriver::class, 'twitter' => \App\Channels\Drivers\TwitterDriver::class, 'email' => \App\Channels\Drivers\EmailDriver::class, ], ];

Adding a New Channel

  1. 1
    Create app/Channels/Drivers/MyChannelDriver.php implementing ChannelDriverInterface.
  2. 2
    Add the driver to config/channels.php under a new key (e.g. 'mychannel').
  3. 3
    Add a webhook route in routes/web.php: Route::post('/webhook/mychannel/{id}', [ChannelWebhookController::class, 'handle']).
  4. 4
    Add the channel type to the channel_type enum migration and re-migrate.
  5. 5
    Add a configuration form partial to resources/views/channels/partials/mychannel.blade.php.
  6. 6
    Add the channel icon and label to config/channels.php's meta section for the UI to pick up automatically.

credentials Encryption

The credentials column on channel_configurations uses Laravel's encrypted:array cast. This means the JSON is serialised to a string, then AES-256-CBC encrypted using APP_KEY before storage. Never access credentials as raw SQL — always go through the Eloquent model.

// Example: reading credentials safely $config = ChannelConfiguration::find($id); $token = $config->credentials['bot_token']; // decrypted automatically // Example: writing credentials safely $config->credentials = ['bot_token' => $request->input('bot_token')]; // encrypted automatically $config->save();

6 AI Engine & RAG Pipeline

RAG (Retrieval-Augmented Generation) is the technique that makes the AI answer questions based on your content rather than just its training data. Here is how it works technically.

Indexing Phase (runs when you add a knowledge base item)

  1. 1
    Content Extraction — PDF items are parsed by pdftotext. URL items are fetched and HTML is stripped. Text/FAQ items are used as-is.
  2. 2
    Chunking — Content is split into overlapping chunks of ~512 tokens with a 64-token overlap (so context is not lost at chunk boundaries).
  3. 3
    Embedding — Each chunk is sent to the configured embedding model (OpenAI text-embedding-3-small or similar) to produce a 1536-dimension float vector.
  4. 4
    Storage — Vectors are stored in the knowledge_base_chunks table alongside the raw text.

Retrieval Phase (runs on every chat message)

  1. 1
    Query Embedding — The visitor's question is embedded using the same embedding model.
  2. 2
    Similarity Search — A cosine similarity query finds the top-K most relevant chunks for this widget (filtered by widget_id).
  3. 3
    Context Assembly — The retrieved chunks are prepended to the AI prompt as a "context" section, telling the AI to prefer this information when answering.
  4. 4
    Generation — The AI generates a response grounded in the retrieved context. If no relevant chunks are found, it falls back to its general training knowledge.

Adding a New AI Provider

All providers implement AIProviderInterface in app/Services/AI/Contracts/. To add a new provider:

  1. Create app/Services/AI/Providers/MyProviderService.php implementing the interface.
  2. Register it in config/ai.php under a new key.
  3. Add the provider name to the ai_model validation rule in the widget settings form request.
  4. Add the provider's API key to .env and config/ai.php.

Rate Limiting

API endpoints are rate-limited per API key: 60 requests/minute for read endpoints, 20 requests/minute for write endpoints. The chat endpoints are rate-limited per visitor IP: 30 messages/minute. Rate limit headers are included in every response:

X-RateLimit-Limit: 60 X-RateLimit-Remaining: 58 X-RateLimit-Reset: 1714000000

Key Events

KnowledgeBaseItemAddedUser adds a document or URLIndexDocument job

Queue Priorities

Jobs are dispatched to three queues with different priorities:

  • high — Chat message processing, webhook sends (user is waiting for a response)
  • default — Email sending, lead notifications, automation triggers
  • low — Document indexing, analytics aggregation, daily report emails

Horizon workers are configured to consume high first, ensuring chat never slows down due to indexing backlog.

Failed Job Handling

All jobs extend ShouldRetry with a maximum of 3 attempts and exponential backoff (30s, 5min, 30min). After 3 failures, the job is moved to the failed_jobs table and an alert email is sent to the admin.

9 Extending the Platform

Adding a Custom Automation Action

Automation actions are registered in config/automations.php. Each action implements AutomationActionInterface:

interface AutomationActionInterface { public function execute(AutomationTriggerEvent $event, array $config): void; public function configSchema(): array; // Fields for the UI form public function label(): string; // Human-readable name }

Adding a Custom Lead Field

Lead capture fields are defined in the widget's lead_fields JSON column. To add a new field type, extend the LeadExtractionService with a new extraction pattern and add the field type to the widget settings form.

Overriding AI Prompt Templates

Prompt templates are stored as Blade views in resources/views/prompts/. You can override the default system prompt template, the RAG context injection template, and the lead extraction prompt without modifying core service files.

Custom Analytics Metrics

To add a new daily metric to the analytics_daily table: add a column via a migration, then add the calculation logic to AnalyticsAggregateCommand::handle(). The analytics dashboard will pick it up if you also add it to the frontend chart configuration.

Push Notifications (VAPID)

VAPID (Voluntary Application Server Identification) keys identify your server to browsers when sending Web Push notifications. The installer generates them automatically via the Minishlink\WebPush\VAPID library using an EC P-256 key pair. If automatic generation fails (uncommon), run the artisan command manually.

VAPID_PUBLIC_KEY=BN... # base64url-encoded EC public key (~88 chars) VAPID_PRIVATE_KEY=... # base64url-encoded EC private key (~44 chars) VAPID_SUBJECT=mailto:admin@yourdomain.com # contact URI sent with each push VITE_VAPID_PUBLIC_KEY="${VAPID_PUBLIC_KEY}" # exposed to Vite for JS bundle
💡

Manual key generation: If VAPID_PUBLIC_KEY is empty after installation, generate keys with:

php artisan webpush:vapid

This writes all three VAPID values directly into .env. Run php artisan config:clear afterwards to apply them. Requires OpenSSL with EC (prime256v1) support — available by default on all modern Linux servers.

11 Production Deployment
