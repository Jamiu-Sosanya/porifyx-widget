PWA Checklist

Use this checklist before going live to verify that every Progressive Web App feature is correctly configured on your server. Each item includes what to check and exactly how to verify it — no guessing required.

Server Admin Pre-Launch Post-Update
ℹ️

This checklist is for server administrators and developers setting up the platform. If you are a regular user wanting to install the app on your phone, see the PWA Guide instead.

A HTTPS & Security

PWAs require HTTPS. Without it, the browser will refuse to register the service worker and the install prompt will never appear.

  • ☐
    SSL certificate is installed and valid
    Verify: visit https://yourdomain.com in a browser. The padlock icon must show as secure (green or locked). No mixed-content warnings.
  • ☐
    HTTP redirects to HTTPS
    Verify: visit http://yourdomain.com (without the s) and confirm it automatically redirects to https://yourdomain.com.
  • ☐
    SSL certificate is not expired
    Verify: check the certificate expiry date using curl -vI https://yourdomain.com 2>&1 | grep expire or use an online SSL checker tool.
  • ☐
    No mixed content warnings
    Verify: open browser DevTools (F12) → Console. No warnings about "Mixed Content" or "insecure content". All resources (images, scripts, fonts) must load over HTTPS.

B Web App Manifest

The manifest file tells the browser how to present the installed app — its name, icons, theme colours, and display mode.

  • ☐
    manifest.json is accessible
    Verify: open https://yourdomain.com/manifest.json in a browser. It should return a JSON file, not a 404 error.
  • ☐
    manifest contains correct name and short_name
    Verify: open the manifest.json file. The "name" field should match your platform name (e.g. "PoriFyx Widget") and "short_name" should be ≤ 12 characters (shown under the home screen icon).
  • ☐
    Icons include 192×192 and 512×512 PNG
    Verify: check the "icons" array in manifest.json. Both sizes must be present. The 512×512 icon is used for the splash screen; 192×192 for the home screen.
  • ☐
    Icon files are accessible
    Verify: copy each icon URL from the manifest and open it in a browser tab. Each must return an actual PNG image, not a 404.
  • ☐
    start_url loads the dashboard, not the marketing page
    Verify: in manifest.json, "start_url" should be "/dashboard" (or your configured dashboard path), not "/".
  • ☐
    display is set to standalone
    Verify: manifest.json should contain "display": "standalone". This removes the browser address bar when the app is opened from the home screen.
  • ☐
    theme_color matches your brand colour
    Verify: "theme_color" in manifest.json should match your primary brand colour (e.g. "#2f5ee8"). This colours the browser chrome and status bar on Android.
  • ☐
    Manifest is linked in the HTML <head>
    Verify: view-source the dashboard page and confirm: <link rel="manifest" href="/manifest.json"> is present inside <head>.
  • ☐
    Maskable icon is included
    Verify: the icons array should include at least one entry with "purpose": "maskable". This allows Android to shape the icon to match the device's icon style. Use maskable.app to preview.

C Service Worker

The service worker is the engine behind offline mode and push notifications. It must be registered correctly to enable PWA capabilities.

  • ☐
    service-worker.js is accessible
    Verify: open https://yourdomain.com/service-worker.js. It should return JavaScript code, not a 404.
  • ☐
    Service worker is registered on the dashboard
    Verify: open the dashboard in Chrome → DevTools (F12) → Application → Service Workers. You should see the service worker listed with status "Activated and is running".
  • ☐
    Service worker scope is / (root)
    Verify: in the DevTools Service Workers panel, the scope should show your full domain (e.g. https://yourdomain.com/), not a subdirectory.
  • ☐
    No console errors from the service worker
    Verify: DevTools → Console. Filter by "Service Worker". No red errors should appear when the page loads.
  • ☐
    Offline fallback page is cached
    Verify: DevTools → Application → Cache Storage → find offline-cache. An offline.html entry should be listed.
  • ☐
    Core app shell assets are pre-cached
    Verify: in Cache Storage, check app-shell-cache contains the main CSS, JS, and font files. These load instantly even offline.

D Push Notifications

  • ☐
    VAPID keys are generated and set in .env
    Verify: .env file contains non-empty VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, and VAPID_SUBJECT. Run php artisan webpush:vapid if not yet generated.
  • ☐
    Config cache has been cleared after setting VAPID keys
    Verify: run php artisan config:cache after updating .env. Without this, the app reads the old (empty) values.
  • ☐
    Push subscription endpoint is working
    Verify: install the PWA on a test device, grant notification permission, then in Admin → System, trigger a test notification. It should arrive on the device within a few seconds.
  • ☐
    Notification icon and title are customised
    Verify: trigger a test notification. The icon should show your logo (not a generic browser icon). The title should show your platform name.
  • ☐
    Tapping a notification opens the correct page
    Verify: when you tap a "New Lead" notification, it should open the leads page. "Conversation Escalated" should open that conversation. Check the notification click handler in service-worker.js.
  • ☐
    Queue worker is running (required for push delivery)
    Verify: Admin → System → Queue Dashboard. Horizon must be running. Push notifications are sent as background jobs — if Horizon is stopped, notifications will not be delivered.

E Installability

  • ☐
    Install prompt appears on Android Chrome
    Verify: open the dashboard in Chrome on an Android device (or Chrome DevTools Device Toolbar). After a few seconds, an install banner should appear at the bottom. If it does not appear, check the Manifest and Service Worker sections above.
  • ☐
    "Add to Home Screen" works on iOS Safari
    Verify: on an iPhone/iPad, open Safari → tap the Share button → confirm "Add to Home Screen" appears in the list. Tap it and verify the icon appears on the home screen.
  • ☐
    Install icon appears in Chrome desktop address bar
    Verify: open the dashboard in Chrome on a desktop computer. A small monitor/install icon should appear at the right end of the address bar.
  • ☐
    App launches in standalone mode (no browser chrome)
    Verify: after installing, open the app from the home screen icon. The browser address bar and navigation buttons should NOT be visible. The app should occupy the full screen.
  • ☐
    Splash screen displays correctly on Android
    Verify: open the installed app on Android. A brief splash screen should appear (with your app icon on the theme_color background) before the dashboard loads.

F Offline Behaviour

  • ☐
    App does not show a blank page when offline
    Verify: load the dashboard, then in DevTools → Network → check "Offline". Refresh the page. The app shell (navigation, layout) should still render, showing cached data or a friendly offline message.
  • ☐
    Offline banner appears when connection is lost
    Verify: load the dashboard, disable your network connection. A yellow "You are offline" banner should appear at the top of the screen within a few seconds.
  • ☐
    Offline banner disappears when connection returns
    Verify: re-enable your network connection after step above. The banner should disappear automatically and the live data should reload.
  • ☐
    Recent conversations are readable offline
    Verify: load the conversations list, then go offline. The previously loaded conversations should still be readable (though new ones will not appear).

G Performance

  • ☐
    Lighthouse PWA score is 90+
    Verify: open Chrome DevTools → Lighthouse tab → select "Progressive Web App" category → Generate report. Target a score of 90 or above. Any failing audits are listed with specific fixes.
  • ☐
    First Contentful Paint is under 3 seconds on mobile
    Verify: Lighthouse → Performance score → check First Contentful Paint metric. Over 3 seconds on a simulated slow 3G connection indicates caching is not working properly.
  • ☐
    App shell loads instantly on repeat visits
    Verify: hard-reload the dashboard (Ctrl+Shift+R / Cmd+Shift+R) to clear memory cache, then reload normally. On the second load, the navigation and layout should appear before the network data arrives.

H Accessibility & Metadata

  • ☐
    Apple touch icon is set
    Verify: view-source the dashboard HTML and confirm: <link rel="apple-touch-icon" href="/icons/apple-touch-icon.png"> is present. This icon is used for the iOS home screen when adding from Safari.
  • ☐
    Apple mobile web app capable meta tag is set
    Verify: view-source shows <meta name="apple-mobile-web-app-capable" content="yes">. Required for iOS standalone mode.
  • ☐
    Status bar style is set for iOS
    Verify: <meta name="apple-mobile-web-app-status-bar-style" content="black-translucent"> or "default" is set. This controls the iOS status bar appearance in standalone mode.
  • ☐
    Microsoft tile meta tags are set (Windows)
    Verify: <meta name="msapplication-TileColor"> and <meta name="msapplication-TileImage"> are set for Windows Start Menu tile appearance.
  • ☐
    Viewport meta tag is set correctly
    Verify: <meta name="viewport" content="width=device-width, initial-scale=1.0"> is present. Without this the app will appear zoomed out on mobile.

I Post-Update Verification

After every application update, re-verify these items to ensure the PWA still works correctly with the new code.

  • ☐
    Service worker version has been incremented
    Verify: open service-worker.js and confirm the CACHE_VERSION constant has changed from the previous release. Without a version bump, users will continue using the old cached assets.
  • ☐
    Old caches are cleaned up
    Verify: in DevTools → Application → Cache Storage, only the new cache version (e.g. app-v2) should exist. Old caches (e.g. app-v1) should have been deleted by the service worker's activate handler.
  • ☐
    Existing installed users receive the update
    Verify: open the installed app on a test device. After a few seconds (or on the next launch), the new version should be active. A "New version available" toast or automatic reload is expected.
  • ☐
    Push subscriptions are still valid after update
    Verify: send a test push notification to a previously subscribed device. If VAPID keys did not change, existing subscriptions remain valid. If keys changed, all users must re-subscribe.
  • ☐
    No broken asset URLs in the new service worker cache list
    Verify: open DevTools Console after the update and check for any 404 errors during service worker install. Every file listed in the service worker's urlsToCache array must exist at that URL.
